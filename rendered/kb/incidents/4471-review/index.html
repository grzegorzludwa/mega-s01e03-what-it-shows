Parser

The shared parser reads month first, although the affected tenants write day first. App and email reports belong here, as do form reports whose tenant uses booking-v2. For example, R-41200 reports 7 April becoming 4 July for Harbour Dental (en-GB). The expected behavior is to interpret the date using the tenant’s date convention. Check the shared parser with an unambiguous day above twelve and an ambiguous day/month pair; no product runtime was supplied, so these are verification scenarios rather than executed product tests.

Booking hint

For a day-first tenant using booking-v3, a form-channel report belongs to hint: the field prints MM/DD/YYYY, but the form reads the date in the tenant’s day-first order. People following the displayed hint can therefore submit a different date from the one intended. For example, R-41241 is an Alder Physio form report (de-DE, booking-v3), while an app report from the same tenant still belongs to parser. Make the hint agree with the form’s interpretation and verify a date entered exactly as instructed. Do not close this ticket merely because the shared parser is fixed.

Some reports describe a one-day move. The desk's exception list is footnoted in the live cause table and stays inside its assigned group. Those descriptions deserve follow-up; they do not establish another cause or justify counting a report twice.

The desk kept receiving reports

Received dates and merge dates answer different questions. The large merge batch is not the start of the incident. Reports continue after that batch: a known ticket and a queued fix are not evidence that the problem stopped. Keep the receipt and merge timelines separate.

How to handle the next report

  1. Find the tenant’s locale and booking-form version in the directory. Browser locale is an intake hint.
  2. Apply causeOf from src/lib/kb/causes.ts using the report channel and that tenant entry.
  3. Merge only when sameCause confirms the same non-null cause. Matching subjects are insufficient; different subjects can still describe the same cause.
  4. If the tenant is missing or the cause is null, leave the report unplaced for investigation.
  5. Deduplicate export overlaps by ID before counting, and retain the report IDs behind each ticket.
